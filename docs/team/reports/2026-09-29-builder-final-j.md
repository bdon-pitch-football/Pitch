## Did

**`lib/legal-doc.ts`: `withholdUnpublished(doc, markdown)`.** `legalDocument` runs it after the preamble strip and before the version line goes in. Four rules, each a removal:

1. **The `[DRAFTED]` label** and the one space after it, with the bold around it if it is bolded alone.
2. **A line carrying `[OUTLINE]` or `[DO NOT PUBLISH …]`** goes whole, together with any italic note paragraph directly under it. That italic-note step is how 6.5's "Status: not built" goes.
3. **`[LEGAL …]`**: the bracketed note goes, with the one space or em dash that attaches it. A line that was only a note goes.
4. **`WITHHELD`**: 13 named removals, each given by its exact words. Each one cuts the words themselves, the line they open (a whole blockquote if they open one), or a section from its heading to the next rule. Each is tagged `held`, `drafting` or `unwritten`.

Tidying happens only where something was removed: one blank line where two met, and one rule where two met. A document nothing is taken from comes back byte for byte, which is why the doc 20 and doc 21 consent hashes are unchanged.

**It throws, rather than serving, in two cases:**
- A `WITHHELD` entry is not found exactly once. For example, John rewords 8.2(b) and the hold would otherwise lapse onto the page.
- A marker survives in a shape the rules do not know.

This follows the file's existing rule that a legal page which cannot be right fails loudly. `/terms` is dynamic, so the throw happens at request time. It is caught before a merge: every suite renders every document, and legj7 proves the throw fires.

## Risks

- **A future John edit to a held or withheld clause makes `/terms` return a 500, and makes a doc 22 consent stamp throw,** until `WITHHELD` is updated. This is deliberate: a hold must not lapse silently. `build:check` does **not** catch it, because the page is dynamic. The permission suite does (legj3–legj7 render every document), so the edit cannot pass the definition of done. It would reach a visitor only if a `docs/legal` edit were deployed without running the suites.
- **legj3's allowed removals are the spec written a second time.** If both the renderer and the test agreed on a wrong rule, both would be green. legj8 pins each rule on hand-written input to limit that.
- **Doc 22's consent hash has changed.** Any dev or preview consent row stamped `22@v2.1` before this commit names text that is no longer served. Production has none, per the brief.
- **Not checked:** the website; a real phone; the club checkout surface the register says shows Schedule A (D-136). I did not find Schedule A rendered anywhere except `/terms`.

## Lesson

A render rule that removes text needs a two-sided property, not a list of spot checks:
- everything served is the source, in order, minus named removals;
- everything unserved is on a pinned list.

The first side catches a rule that eats a word. The second catches one that takes a paragraph too many. Here the first side alone let a mutant through: a drop rule that also took the next clause (M6) kept legj3 green, and only legj4 caught it.
