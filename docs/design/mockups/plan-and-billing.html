Plan & billing, set properly

82% empty at 1440, and the price of the whole business is set three pixels larger than its own label — because the label's class does not exist on this page. This supersedes club-billing.html (23 Sep), which proposed the same content and was not built. The new part is the setting, not the words.

What is wrong now, and one line of it is a real bug

The page is a named console surface in D-147 (ClubBilling) rendering as a 604px reading column: 75% empty at 1024, 80% at 1280, 82% at 1440, page height 889px against an 816px viewport. Four elements and a Back link.

Then the setting. app/club/billing/page.tsx:68 writes <div className="field-label">Your plan</div>, and the only rule for that class in the stylesheet is .field > .field-label (globals.css:307) — a direct-child selector. The div is inside a card, not a .field, so the rule never matches and the caption renders as ordinary inherited body text. That is why "Your plan" and "$54 a month" are three pixels apart. The same defect appears on /club/post-trial (8×), /club/invite (2×) and /register-interest (4×) — 19 captions across four files, including this page’s five, every one of them rendering as body text. (/club/roles, /club/squads, /club/page-edit, /join and /squad use the class correctly, inside a real .field, which is what makes this easy to miss.) It is a one-line CSS fix (make the selector .field-label, not .field > .field-label) and it is worth more than anything else on this page.

And .numeral-l and .card-sunken are both defined in the stylesheet this page already loads, and this page uses neither.

What the change does for the person on this screen

A treasurer opens this page to answer three questions: what are we on, when does it go out again, and what is PITCH FOOTBALL on our statement. Today the page answers one and a half. Here the price is a display numeral because it is the fact the page exists for, the charge date sits beside it at the same rank, and the facts a treasurer has to quote to a committee — descriptor, receipt address, who agreed and when — are in a sunken well, because you read them rather than act on them. Exactly one thing on the screen is green: the only button.

What it costs to build

Half a day, plus one line of CSS. The plan, the renewal date, the descriptor, the authority record (D-137 captures the name, the role and the tick) and the cancel route are already on the page or already on the row. The layout is the console grid /club/register already uses. The one block that is not free is What you have paid — charges are not stored today, only subscription state, so it needs an invoice.paid webhook writing a row. Ship the page without it if that is a day we do not have; a treasurer asking for a receipt is the trigger to add it.

What it does NOT change

Not the price, not the plans, not one word of the D-136 disclosure or the D-137 authority tick. Not the checkout form, which is already good and only gains the second column. Not where cancelling lives. Not the phone: at 390 it is the same content in the same order, one column, rail blocks stacked underneath. No new copy at all — every string on the proposed screens below is lifted from the built page except the four underlined ones.
